# Threat model

What Airlock protects against, and what it does not. Read this before relaxing anything in
`src/kernel/policy.ts`.

The short version: several rules that look paranoid are load-bearing against specific published
attacks, and a few plausible-sounding controls were deliberately **not** built because they do
not work.

---

## The invariant

> No individual-level value is released through the registered tool interface or rendered to
> the DOM, under the stated disclosure policy. The page's own memory is out of scope. This is
> not a cryptographic boundary.

Every clause is deliberate. Earlier drafts claimed something stronger — "the agent never sees
any individual record through any channel" — which is not defensible, for reasons in
[Out of scope](#out-of-scope).

| Layer | Contains | Enforced by |
|---|---|---|
| Raw store | Generated records, in memory only | `#rows` private field + `boundary.test.ts` |
| Privacy kernel | The only code with raw access | Single entry point |
| Policy | Floors, allow-list, quantization, banding, budget | `policy.ts`, unit-tested independently |
| Tool output | Kernel results only | No tool handler may read the raw store |
| DOM | Aggregates only | No individual attribute reaches a text node |
| Canvas | Aggregates only | Every mark represents at least `K_COUNT_FLOOR` records |
| Ledger | Query metadata | Records what was asked, never what was returned |

---

## Who the adversary is

**Not the agent.** This matters, because getting it wrong produces an incoherent design.

If the agent were the adversary, a human clicking "approve" would be a trivial bypass and the
whole guarantee would reduce to "the user will not be tricked." If the agent were fully
trusted, none of the machinery would be needed — you would simply not upload the file.

The actual requirement is **provable data minimisation**: being able to demonstrate that no
personal data was processed by a third party. That is the GDPR anonymisation question
(Art. 4(1) and Recital 26 — whether an individual can be *singled out*), not an adversarial
one.

Two consequences follow:

- **The ledger is the product.** The analysis is the demo. An append-only record of every
  question asked, every refusal issued, and every human override granted is the artifact that
  survives an audit.
- **Human override is accountability, not a security hole.** A documented decision by the data
  controller is exactly how real governance works. It is not a bypass of a security boundary,
  because the boundary is a policy boundary.

## What is enforced

### 1. Bounded tool vocabulary

Dimensions and metrics are enums. No free-form query strings, no filter expressions, no
agent-supplied predicates.

**Necessary but not sufficient.** Bounding the vocabulary bounds *syntax*, not
*expressiveness*: the lattice generated by a handful of enums still spans a large predicate
space. `MAX_GROUP_BY_DEPTH` is what actually limits it.

### 2. Two floors, not one

`K_COUNT_FLOOR = 5` for counts. `N_NUMERIC_FLOOR = 20` for any statistic that reads a metric's
values.

The second is the single most important number in the codebase. **At small n, order statistics
*are* individual values.** With the standard linear-interpolation quantile definition
(index = `(n-1) * q`, numpy default / R type 7), at n=5 the median is exactly the third
person's salary, and p25 and p75 are the second and fourth. A k=5 floor on a statistic whose
influence support is 1 is not a floor.

There is a test asserting the numeric floor stays at least 4× the count floor, so the two
cannot quietly converge during a refactor.

### 3. Statistics allow-list

Permitted: `count`, `mean`, `median`, `p25`, `p75`.

Each exclusion closes a specific attack:

| Excluded | Why |
|---|---|
| `min` / `max` / top-N | An extremum **is** an individual's value. |
| `stddev` / `variance` | A zero-variance cohort discloses every member exactly — the homogeneity attack that motivated ℓ-diversity (Machanavajjhala et al., ICDE 2006). Banded pay data produces such cohorts routinely. Worse, `mean + stddev + count` bounds every observation via Samuelson's inequality (JASA 1968), and combined with quartiles yields closed-form recovery of min and max. |
| `sum` | Sums difference cleanly across nested cohorts, and sum + any overlapping count is a mean. |
| `mode` | The modal value is an observed value. |

### 4. Output quantization

Currency to `CURRENCY_QUANTUM`, ratios to 2dp, percentage points to 0.5.

**Honest about what this is:** a coarsening, not a guarantee. Deterministic rounding does not
prevent reconstruction — the error is a known function of the true value, so it never averages
away and it composes into a linear program with bounded slack. That is precisely how the 2010
US Census was reconstructed from published, rounded, suppressed marginals (Garfinkel, Abowd &
Martindale, CACM 2019). Quantization raises the cost; it does not close the class.

### 5. Banded counts

No exact count below `COUNT_EXACT_FLOOR = 50`.

Exact small counts are the missing ingredient for several attacks: they identify which cohorts
sit at the floor, which is exactly where the remaining attacks are strongest.

### 6. Budget denominated in released cells

Counting tool *calls* was a design error caught in review. One grouped query returns a whole
table, so a 60-call budget can release thousands of cells while appearing tight. Cells are what
an adversary actually spends, so cells are what the budget counts.

### 7. Data-independent refusals

Refusal text is a pure function of the refusal *code*. A message like `insufficient support:
n=4` publishes the very count banding exists to hide, and turns every refusal into a one-bit
oracle that can be walked to locate the smallest cohorts. Enforced by a test asserting
`refuse.length === 1` and by a scan for stray digits.

Refusals are **returned as values, never thrown**. The WebMCP spec discards a rejected
promise's reason: the caller receives a generic `UnknownError` and the message is lost. An
agent that cannot read why it was refused cannot adapt.

### 8. Free-text columns dropped at parse time

Job titles and performance notes never enter memory. They are a prompt-injection vector, and
rare-term co-occurrence in a small cohort is a fingerprint. Parse errors report column index
and row number only — never cell contents.

### 9. Aggregate-by-construction charts

Fixed-bin histograms drawn to canvas from already-quantized aggregates. No chart library, no
tooltips, no `aria` value labels, no raw arrays reaching a rendering layer.

Box plots and violin plots were **removed after review**. A box plot renders outliers as
individual dots — it is the canonical individual-disclosing chart. A violin plot is a density
estimate over individual points. Both were in an earlier draft's list of "aggregate-by-
construction" charts, which was wrong.

## Deliberately not built

**A differencing detector.** An earlier design hashed each query's group specification and
flagged pairs differing by one bucket. It was cut, and this is the most instructive decision in
the file:

- It watches the *group* axis. Sweeping histogram bin counts attacks the *value* axis and would
  pass unnoticed.
- Grouped queries return tables, so a cohort and its complement arrive inside a *single* query
  at Hamming distance 0. A pairwise test can never see it.
- Reconstruction requires the target indicator vector to lie in the span of queried predicates.
  That is a rank condition, not an adjacency condition. Choose a spanning set with pairwise
  distance ≥ 2 and any pairwise check is defeated.
- It was the most expensive item on the roadmap and the least effective.

**Differential privacy with ε accounting.** Considered and rejected for this build. Correctly
calibrated DP requires derived sensitivity bounds per query type; an uncalibrated ε claim is
worse than no claim, because it converts a careful project into an overclaiming one. Noise
would also make the demo non-deterministic. Named here as the honest next step rather than
implied by vague language.

## Out of scope

Stated plainly, because a precise limitation is more credible than a broad claim.

**The page's own memory.** The raw records live in the tab. An agent that can execute
JavaScript in that tab can read them. The tool interface is a policy boundary, not a sandbox.

**Rendered pixels.** ChatGPT's Computer Use can screenshot the page. This is why nothing
individual is rendered *at all* — the mitigation is architectural rather than a claim that the
channel does not exist. Charts are aggregate-by-construction so that a screenshot yields only
what a tool call would have yielded.

**Background knowledge.** An analyst who already knows four salaries in a cohort of five can
derive the fifth from its mean. This is irreducible for any system that reports means, and it
is the reason `N_NUMERIC_FLOOR` is 20 rather than 5.

**Marginal reconstruction.** Mitigated by the group-by depth cap, the numeric floor, and the
cell budget. Not eliminated. Given enough overlapping marginals, integer programming over a
quantized value grid narrows individual values (Dinur & Nissim, PODS 2003: noise must be
Ω(√n) to prevent reconstruction; deterministic rounding is not noise).

**The human.** A person under task pressure who approves every override request degrades the
policy to whatever the agent asks for.

What is actually implemented: requests are per-query rather than a blanket policy change; a
decision cannot be replayed, because resolving an already-resolved request is a no-op; requests
expire after two minutes, which also prevents a stale request keeping `check_override_request`
registered as a free polling channel; and even an approved override is clamped so it can never
approach the count floor.

What is not: the agent writes the justification text. The page generates the description of *what
would be revealed*, and the agent's words are rendered as a marked quotation — but a persuasive
justification is still a persuasive justification. This is a mitigation, not a solution.
